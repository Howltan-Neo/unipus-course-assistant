# 最少人工干预的启动与续接

用户给出课程链接和范围后，直接检查工具、安装位置及已有进度；缺少关键授权时一次问清，不把每份试卷变成一次确认。遵守用户排除项。

1. 识别现有浏览器能力，优先复用已登录会话。采用宿主允许的工具。DOM只读工具只能做提取，不能执行本包的填入函数；使用它提供的点击/填写方法完成写入。允许浏览器脚本时才运行DOM助手。缺少浏览器能力时明确说明安装技能还需要浏览器工具，不能假称已经开始。
2. 打开指定课程，需要身份验证时让用户亲自完成，只要一次“已登录”回复。先读取页面账号与课程，避免误操作其他账号。
3. 一次读取目录及说明规则，建立待办类型与状态。用户预先授权作业试运行成功后批量继续的，试运行通过即可继续；用户要求另行授权的，保留其门槛。单次测试授权明确后逐份执行，期末考沿用同一流程。次数未知且无法查明的跳过并汇总。
4. 真实视频脚本与答题使用各自页面，避免播放器导航覆盖活动试卷；有计时的试卷同时只开一份。同课程可用内置视频资产，新课程自行适配，不要求用户提取源代码。不能直接注入持续脚本时尝试平台控制或安装允许的脚本；只能用户安装时给出一次粘贴操作。
5. 普通作业重试遵循用户限制，未规定时反馈后最多重试两次，仍有错则记录继续其他项目。一次性项目提交出现不确定结果时只查状态，不重复提交。没有足够材料或存在未解决的重要歧义时，记录异常，不用盲猜承诺满分。
6. 只写一个精简进度文件：课程URL、各任务ID/类型/规则/状态、核验结果、异常、下一步。登录信息和完整答案不写进共享仓库。持续执行直到授权任务完成或确有人工阻塞；稳定视频由浏览器脚本监测。
7. 浏览器脚本能在浏览器保持打开时工作，技能文件本身不会让停止的智能体自动继续答题。只有用户要求定时或后续监测时才使用宿主调度工具；不能靠把任务写进文档冒充后台服务。
8. 结束后汇总实际结果一次，按用户指令清理本地临时题目、答案与快照。用户不要求继续核验的历史项目不反复追查或提醒。
